# Design Specification: Product Builder's Portfolio (Utilitarian Minimalist)

This specification defines the foundational design tokens, visual hierarchy, and core aesthetic rules for a workspace optimized for readability, rapid execution, and technical pragmatism.

## 1. Vibe & Intent
- **Core Principle**: Utilitarian, brutally minimalist, strictly optimized for readability.
- **Aesthetic**: Signal technical pragmatism. No gradients, no soft shadows, no glassmorphism, no decorative patterns.
- **Visual Language**: High contrast, sharp edges, and purposeful whitespace.

## 2. Typography
- **Primary Font**: Inter (Sans-Serif) - Clean, high-contrast, neutral.
- **Type Scale**: Strict 1.250x (Major Third) scale.
  - **Display (H1)**: 48px / 1.1 LH / Extra Bold (800) / Tracking -0.02em
  - **Header (H2)**: 32px / 1.2 LH / Bold (700) / Tracking -0.01em
  - **Subheader (H3)**: 24px / 1.3 LH / Semi-Bold (600)
  - **Body (Primary)**: 16px / 1.6 LH / Regular (400)
  - **Body (Secondary/Caption)**: 14px / 1.5 LH / Regular (400)
  - **Monospace (Code/Data)**: 14px / 1.5 LH / Geist Mono (Technical metadata)

## 3. Color Palette (Monochrome + Utility Accent)
Strict adherence to high-contrast accessibility and functional signaling.

| Token | Value | Usage |
| :--- | :--- | :--- |
| `color-bg-base` | #FFFFFF | Primary background |
| `color-bg-surface` | #F4F4F5 | Cards, secondary sections, subtle separation |
| `color-text-primary` | #09090B | Headers, primary body copy (Maximum contrast) |
| `color-text-secondary`| #71717A | Metadata, secondary body copy, descriptions |
| `color-accent-utility`| #2563EB | Sharp Technical Blue: CTAs, active states, critical status |
| `color-border-base` | #09090B | Structural borders (1px) |
| `color-border-muted` | #E4E4E7 | Decorative or secondary structural lines |

## 4. Spacing & Grid
- **Base Unit**: 8px.
- **Spacing Tokens**:
  - `space-tight`: 8px (Small gaps, internal component padding)
  - `space-medium`: 24px (Component-to-component spacing)
  - `space-generous`: 64px (Section-to-section layout separation)
- **Layout Rule**: Rely on whitespace for separation. Avoid horizontal dividers unless absolutely necessary for data density.

## 5. Borders & Effects
- **Radius**: Sharp corners. `0px` for large containers, `4px` maximum for interactive elements (buttons, inputs).
- **Strokes**: `1px solid` for structural elements.
- **Shadows**: Strictly `none`. Separation is achieved via background color contrast (#F4F4F5 vs #FFFFFF) or 1px borders.

## 6. Component Rules
- **Buttons**: `color-bg-base` with `color-border-base` (Secondary) or `color-accent-utility` (Primary). Rectangular, high-weight text.
- **Cards**: Background `color-bg-surface`, no shadow, 1px border `color-border-muted`.
- **Inputs**: 1px border, sharp corners, no glow effects on focus—use 2px border or accent color instead.
